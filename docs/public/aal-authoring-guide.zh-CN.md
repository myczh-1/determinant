# AAL 编写指南

> 默认英文版本：[AAL Authoring Guide](./aal-authoring-guide.md)

## 语言定位

AAL（Auditable Application Language，可审计应用语言）是一种面向应用行为、给人审计的正式语言。

它描述：

- 世界中有哪些数据和状态；
- 流程会进行哪些计算和判断；
- 哪些状态会被明确改变；
- 多个业务流程如何组合；
- 成功输出和失败条件是什么。

用户确认 AAL 后，确定性解析器、语义检查器和 TypeScript 生成器负责后续处理，不再让 LLM 推断缺失的业务决定。

## 方言

英文是默认方言，无语言后缀的文件使用英文。

中文文件使用 `.zh-CN.aal` 后缀，并通过 `--language zh-CN` 编译。

两种方言进入同一套 AST、检查器、Binding 解析和代码生成流程；它们只是同一核心语义的两种人类表层。

## 给生成 AAL 的 AI 的规则

1. 只输出 AAL，不要把 TypeScript、JavaScript 或伪代码当成 AAL。
2. 应用标题后，用户表层只使用 `对象` 和 `流程` 两种顶层声明。
3. 字段关系统一写成 `库存 的 数量`，不要使用点号、方括号、`this`、方法或调用等实现语法。
4. 不要自行补全字段、类型、币种、单位、精度、权限、重试、并发、回滚、舍入或失败行为。
5. 每个对象字段和流程输入都必须有明确类型。
6. 真实状态变化必须写在 `改变` 下；计算本身不会改变对象。
7. 流程组合必须显式写出 `执行`、`使用` 和 `得到`。
8. 业务需求存在歧义时先询问用户。
9. 用户确认 AAL 后，停止继续改变业务含义。

## 文件结构

每个文件必须从一个应用标题开始。P0 至少需要一个对象和一个流程：

```aal
应用：库存应用

对象：库存

    数量：整数

流程：读取库存

    输入：
        库存：库存

    输出：
        数量 = 库存 的 数量
```

每层缩进使用 4 个空格。空行和以 `#` 开头的行会被忽略。

名称必须以字母或下划线开始，后面只能包含字母、数字或下划线；Unicode 汉字属于字母。名称中不能出现空格。

## 对象与字段

对象只描述数据和状态，不包含流程：

```aal
对象：订单

    编号：整数

对象：库存

    数量：整数
```

读取多层字段时使用 `的`：

```text
订单 的 编号
订单 的 用户 的 姓名
```

`订单.编号` 这样的点号访问会被拒绝。

## 类型

P0 支持以下声明：

```text
整数
文本
布尔
人民币金额
美元金额
已声明对象的名称
```

例如，声明 `对象：库存` 后，`库存` 就可以作为类型使用。“对象名称”四个字本身不是类型关键字。

内置金额类型当前使用固定标准表示：

```text
人民币金额 = 币种 CNY，单位 yuan，2 位小数
美元金额 = 币种 USD，单位 dollar，2 位小数
```

也可以明确写出单位标签：

```aal
单价：人民币金额，单位为元
```

编译器会把内置的 `元` 和 `美元` 归一化为运行时使用的 `yuan` 和 `dollar`。P0 的金额精度仍固定为两位小数，暂不支持自定义精度。非标准单位必须来自用户确认的业务需求，不能由 AI 或编译器猜测。

P0 表达式目前只有整数常量。文本和布尔可以作为字段或输入类型，但尚未实现文本常量和布尔常量语法。

## 流程

流程描述应用中会发生什么：

```aal
流程：扣减库存

    输入：
        库存：库存
        数量：整数

    如果 数量 <= 0：
        失败：数量必须大于零

    如果 库存 的 数量 < 数量：
        失败：库存不足

    改变：
        库存 的 数量 = 库存 的 数量 - 数量

    输出：
        剩余库存 = 库存 的 数量
```

每个流程都必须有 `输出`。`如果` 的条件必须是布尔条件，下一个有内容且正确缩进的行必须写出对应的 `失败` 消息。被执行流程失败时，同一个失败结果会传递给当前流程。

## 计算与状态改变

计算会命名一个派生值，但不会修改状态：

```aal
计算：
    总价 = 单价 * 数量
```

只有 `改变` 表示真实对象状态发生变化：

```aal
改变：
    库存 的 数量 = 库存 的 数量 - 数量
```

`改变` 的目标必须是对象字段。输入、计算结果和流程输出不能被直接修改。

## 流程组合

执行另一个业务流程时必须显式写出：

```aal
执行：
    计算订单总价

    使用：
        单价
        数量

    得到：
        总价
```

`使用` 按被执行流程声明的输入顺序对应参数；`得到` 按输出顺序接收结果。编译前会检查输入数量、输出数量和类型。

## 表达式与运算符

解析器识别：

```text
+  -  *  /  %  >  >=  <  <=  ==  !=  (  )
```

`=` 用于计算、改变和命名输出；相等比较使用 `==`。

P0 类型检查允许：

- 整数算术；
- 币种、单位和精度完全一致的金额相加或相减；
- 金额与整数按任意顺序相乘；
- 兼容类型之间的比较。

整数 `/` 当前沿用生成 TypeScript 的数值除法语义。长期的整数舍入规则尚未正式定义；如果结果可能出现小数，在业务规则单独确认前不要使用它。

## Binding

AAL 使用审计名称。可选的 [Binding 文件](./binding-guide.zh-CN.md)可以把 `订单` 下的审计字段 `编号` 保持为稳定 ID，同时生成程序字段 `id`。

不提供 Binding 时，编译器会为本次构建生成确定性后备绑定。如果 ID 或程序名称需要跨源文件重命名、声明顺序变化保持稳定，就应使用显式 Binding。

Binding 是独立构建输入，不能增加隐藏业务规则。

## 完整示例与编译

完整中文示例位于 [examples/order.zh-CN.aal](../../examples/order.zh-CN.aal)，包含订单总价计算、库存扣减和创建订单三个流程。

```bash
npm run compile:example:zh
```

当前 P0 将最后声明的流程作为生成程序的 `run` 入口。未来的多入口协议必须显式声明，不能依靠名称猜测。

## 当前 P0 限制

P0 尚未提供：

- 多个显式外部入口；
- 文本或布尔常量；
- 自定义金额精度；
- HTTP、CRUD、持久化或事务；
- 第三方 API、SDK 或数据库适配；
- 重试、并发、权限或回滚语义。

不要使用隐藏约定模拟这些能力。

## 审计清单

- [ ] 文件是否从唯一的应用标题开始？
- [ ] 其余顶层声明是否只有对象和流程？
- [ ] 每个对象字段和流程输入是否都有类型？
- [ ] 每个金额是否明确人民币或美元，非标准单位是否经过确认？
- [ ] 每个字段关系是否使用“的”，而不是点号？
- [ ] 所有状态变化是否显式写在“改变”中？
- [ ] 所有流程组合是否写明“执行 / 使用 / 得到”？
- [ ] 所有失败条件和消息是否明确？
- [ ] AI 是否避免自行补全业务决定？
